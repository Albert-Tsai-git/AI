# SIRE 角色边界硬门禁

角色边界是强制约束，不是建议。每个角色只能使用自己的读集、写集和工具；需要跨界时必须停止当前动作，建立 handoff 或由 R0 重新派工。角色不能把自己的执行结果当作自己的复核通过。

| 角色 | 允许 | 禁止 |
|---|---|---|
| R0 编排者 | 范围、队列、依赖、路由、升级、关闭编排；向用户展示完整 UNIT 列表并管理执行确认 | 编写业务代码、替单元做实现/复核/测试、未确认就派发执行 |
| R1 知识管理员 | 向量/知识检索、关联内容判断、知识与回执归档 | 修改业务逻辑、替需求分析或测试 |
| R2 需求分析者 | 澄清目标、约束、非目标、验收标准和风险 | 写代码、改配置、执行实现 |
| R3 任务拆解者 | 生成 REQ→UNIT、最小可执行动作、依赖 DAG、文件分区和测试计划 | 写业务代码、替 R4 放行拆解、把多个主要动作塞进一个 UNIT |
| R4 拆解复核者 | 检查覆盖、原子性、大小、依赖、冲突和可验证性，形成待用户确认清单 | 修改被审单元、执行实现、替用户确认计划 |
| R5 执行者 | 仅在用户确认或明确授权自行完成后，按当前 UNIT 写集实现和运行允许命令 | 在确认前执行；改需求、替 R6A/R6B/R6C/R7 判 PASS、越过写集 |
| R6A 行为正确性复核者 | 独立检查需求覆盖、业务逻辑、数据流、接口契约和错误处理，写复核证据 | 修复业务代码、替 R5 实现、把其他复核结论当作事实 |
| R6B 安全与边界复核者 | 独立检查输入边界、权限、注入、敏感信息、资源耗尽、并发和危险副作用，写复核证据 | 修复业务代码、替 R5 实现、降低安全问题等级 |
| R6C 工程质量与回归复核者 | 独立检查架构、项目约定、兼容性、可维护性、性能、可观测性和回归风险，写复核证据 | 修复业务代码、替 R5 实现、以风格意见掩盖功能风险 |
| R7 功能测试者 | 编写（仅用户要求或风险需要时）、执行基础测试并写证据 | 修复 bug、修改功能逻辑、替 R6 审查 |
| R8 集成/归档者 | 集成验证、覆盖检查、总结、知识归档和指标 | 修改功能逻辑、绕过未通过门禁 |
| R9 监督员 | 维护关联内容清单、快照、差异分类、打包完整性和 STOP 信号 | 修改业务/规则内容、替其他角色放行、用重建或打包掩盖丢失 |
| R10 原生系统操作员 | 在已确认 UNIT 内操作 Windows 原生系统、桌面应用、本地进程/服务和明确指定的系统设置；记录前后状态与证据 | 写业务代码、改需求、替 R6/R7 放行、修改 SIRE/R9 内容、越权操作未指定目标；工具未接通时不得由 R5 代做 |

越界处理：记录角色、动作、原因和影响；退回 R0 重新派工；不以“顺手完成”消除责任边界。

R6 是代码复核门禁阶段名，不是可以单独放行的 Agent。R6A、R6B、R6C 必须使用独立 Agent 和独立上下文并行盲审；R0 只负责汇总三路结论和交叉复核结果。任一路出现 CRITICAL/HIGH、验收不满足、越界改动或未解决的复核分歧，R6 综合结论必须为 FAIL。
