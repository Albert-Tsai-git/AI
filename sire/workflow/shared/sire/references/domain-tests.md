# SIRE 显式前缀领域测试规范

本文件只定义可执行验收合同，不把结构断言当成审美或业务质量证明。所有显式 `sire` 任务仍必须由 R6A/R6B/R6C、R7 和 R8 按单元闭环；下面的领域项用于 R3 选测试，不要求每个任务同时覆盖所有领域。

## 游戏

- 正常路径：验证规则初始化、输入接受、状态转移和胜负/完成路径。
- 边界/异常路径：验证最小/最大输入、非法输入、重复操作和终止状态后的操作。
- 不能只测试“页面存在”或“代码可运行”，必须观察至少一个状态结果。

## 音乐

- 正常路径：验证音符/事件结构、时值总和、速度或拍号等明确约束，并在环境可用时渲染或播放检查。
- 边界/异常路径：验证零/负时值、空事件、总时长偏差和不支持音高/格式的处理。
- 节奏和格式可自动验证；旋律审美、情绪和风格由独立复核官评审。

## 解析

- 正常路径：验证代表性合法输入、字段/节点输出和必要的往返或序列化结果。
- 边界/异常路径：验证空输入、缺字段、非法语法、嵌套边界、超长输入和类型错误。
- 失败结果必须可定位到输入位置或错误类别，不能把异常吞掉后报告成功。

## 文学

- 正常路径：验证主题/意象、长度、结构、角色或叙事约束，以及前后文一致性。
- 边界/异常路径：验证缺失主题、超长、角色动机冲突、时间线矛盾和禁用元素。
- 结构与约束可测试；文风、感染力、隐喻质量和文学价值必须单独由 R6A/R6C 或用户验收，R6B 负责适用的安全与边界风险。

## 创造

- 正常路径：验证输出 schema、必填字段、用户指定限制、内部因果和可继续加工性。
- 边界/异常路径：验证空主题、缺少关键参数、互斥约束、重复结果和不安全/未授权方向。
- 新颖性和审美不是单元测试可独立证明的事实，必须记录独立复核结论和未覆盖的主观部分。

## 最小测试记录格式

```text
领域: [游戏/音乐/解析/文学/创造]
正常路径: 输入 → 期望 → 实际
边界/异常: 输入 → 期望 → 实际
独立复核: 结构/事实/语义/风格结论
证据: 命令、输出、截图或渲染文件路径
```
