# 持续学习与自我优化规则

本文件定义如何收集用户工作习惯、编码习惯和流程反馈，并安全地更新工作流。它只补充学习机制；SIRE 的门禁、权限、状态和知识归档规则仍由当前主 Skill 负责。

## 1. 观察来源

只记录与开发任务直接相关、可复现的事实：

- 用户明确提出的长期偏好，例如“以后默认使用……”“所有项目都……”。
- 用户反复接受或纠正的代码风格、目录结构、测试方式、注释语言、Git 流程、输出格式和模型选择。
- 任务中实际测得的耗时、返工、测试失败、模型升级和工具使用结果。
- 用户对流程提出的纠正、取消或新增规则。

不推断敏感属性、身份、财务状况、健康状况、密码、令牌、私有数据或与开发无关的个人特征。

## 2. 置信度与状态

| 状态 | 条件 | 处理 |
|---|---|---|
| observation | 单次行为或未验证推断 | 只写当前 run，不改变默认行为 |
| candidate | 用户明确表达一次，或同类行为出现两次 | 可在当前项目试用，标记待复核 |
| active | 用户明确要求长期采用，或候选经独立复核并在后续场景验证 | 写入 H/E/P 知识记录并应用 |
| retired | 用户明确取消，或后续证据表明不再适用 | 标记废弃，不删除历史证据 |
| conflict | 与当前指令、项目规则或旧习惯冲突 | 当前指令优先，记录冲突，不自动覆盖 |

一次性选择不能直接升级为全局默认。若用户明确表达“以后/默认/都按此处理”，可将它作为高置信度候选，但仍要检查是否只适用于当前项目。

## 3. 记录位置与字段

任务中在当前 SIRE `RUN_DIR/learning/observations.md` 记录观察，在 `RUN_DIR/learning/proposals.md` 记录拟议变更。每条记录至少包含：

```yaml
observation_id: OBS-001
date: YYYY-MM-DD
source: user_explicit|accepted_change|repeated_pattern|failure|metric
evidence: "用户原话、任务编号、文件路径或测试记录"
behavior: "观察到的可复现行为"
scope: task|project|all-development
confidence: low|medium|high
candidate_action: "如果固化，具体改变什么"
conflicts: []
status: observation|candidate|active|retired|conflict
```

## 4. 晋级与更新流程

```text
R1 收集观察
  → R0 判断作用范围
  → R6 独立复核是否过度泛化或违反约束
  → R7 用后续案例/回归场景验证
  → R1 归档 H/E/P 记录并重建索引
  → R0 应用低风险偏好或提出需要确认的 Skill 变更
```

低风险偏好可以自动应用：输出格式、注释语言、测试展示方式、常用命令和默认检索顺序。以下改变必须获得用户明确确认：

- 放宽文件、网络、凭据、生产或外部写入权限；
- 取消或降低知识检索、独立复核、功能测试、集成验收或归档门禁；
- 改变 `sire` 前缀触发边界；
- 提高自动提交、自动合并、自动部署或自动通知的权限；
- 改变模型成本上限、数据保留或隐私策略。

工作流自身的修改必须先写提案，再生成最小 diff，执行结构校验和一个代表性回归任务；失败则回滚提案，不把新规则标记为 active。

## 5. 优先级与回滚

优先级固定为：当前用户指令 > 项目规则/安全约束 > 当前任务验收条件 > 已确认习惯 > 候选习惯 > 默认策略。历史习惯永远不能覆盖当前明确指令。

每次固化变更写明：原规则、变更内容、理由、证据、影响范围、验证结果、日期和回滚方式。用户说“恢复之前的方式”或新证据显示质量下降时，将该记录标记 `retired`，恢复上一条已验证规则，并保留审计记录。

## 5.1 RSI 改进门禁

工作流机制改进必须遵循：提案 → 基线指标 → 独立评估 → 版本化激活 → 后续观测 → 必要时回滚。不得仅因一次任务成功就将机制标记为长期有效。

每个改进提案至少记录：提案编号、改进假设、变更摘要、父版本、基线指标、目标指标、实际指标、证据、评估结论、激活版本和回滚原因。评估未达到目标时不得激活；激活后出现回归时必须恢复上一版并保留失败证据。

本地数据库表 `improvement_proposals`、`improvement_metrics` 和 `workflow_versions` 是 RSI 审计记录的权威来源，可通过 `scripts/sire_rsi.py` 执行提案、评估、激活、状态查询和回滚。写命令先写机器级归档库（`SIRE_ARCHIVE_DB` 或 `SIRE_ARCHIVE_ROOT`，或 `--archive-db`），再写仓库库；解析不到归档库时拒绝写入（仅测试可用 `--repo-only`）。`status` 只读。`snapshot_db.py` 发现仓库库有而归档库缺失的 RSI 记录时拒绝发布。

## 6. SIRE 知识归档映射

- 用户工作习惯和编码习惯 → `global_dev_habits.md`，编号 `H-xxx`。
- 流程提效、模型路由和工具链经验 → `global_dev_efficiency.md`，编号 `E-xxx`。
- 失败模式和修复方法 → `global_problem_solutions.md`，编号 `P-xxx`。

使用 `sire_kb.py next-id H|E|P`、追加结构化记录并运行 `sire_kb.py reindex`。不要手写 `global_index.json`，不要把临时日志或敏感内容归档到全局知识库。
