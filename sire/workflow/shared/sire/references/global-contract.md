# 全局 SIRE 执行规则

所有任务，无论简单、复杂、分析、问答、创作、代码、配置或外部工具操作，均必须使用 SIRE 工作流执行。

每次回复必须明确告知用户：`[SIRE v6] 已使用 SIRE 工作流执行当前任务`。

任务开始前必须检索 SIRE 本地知识库和向量数据库；任务结束后必须将可复用知识、任务记录和验证结果同步到机器级归档数据库 `@SIRE_ARCHIVE_ROOT@\sire_vectors.sqlite3`。除下方“简单任务快速通道”外，不得因任务简单而跳过 SIRE 声明、检索、记录或归档要求。

## 简单任务快速通道（每次执行强制确认一次）

每次执行 SIRE，在做任何检索、分析或拆解之前，必须先确认一次“是否简单任务”。Claude 与 Codex 同样执行，不得省略这一步。

**简单任务**须同时满足：
1. 只读查询或即时问答，例如查看当前分支、某个文件或配置的值、某条命令的输出、某个概念的一句话解释；
2. 一到两个只读命令或直接知识即可得到答案；
3. 不修改文件、配置、数据库、Git 或任何外部状态；
4. 不需要设计取舍、方案选择或验收测试。

任一条不满足，即按完整 SIRE 流程执行。拿不准时按完整流程。

**是简单任务时**：
- 回复只包含三部分：第一行 `[SIRE v6] 已使用 SIRE 工作流执行当前任务`；第二行 `快速通道：简单任务`；然后用最短的话直接给出答案。例如：用户问“查看当前分支”，答案就是“当前分支：`main`”。
- 跳过知识库/向量检索、R0–R10 阶段日志、模型选择门禁、运行台账、归档和 Git 提交。
- 不加解释、建议、追问、额外检查或“顺便”做的事。
- 答案必须来自本次实际执行的命令或读取的内容，不得用记忆、知识库或历史记录代替。
- 执行中发现需要修改或多步处理，立即停止快速通道，用一行说明“转完整流程”，再按完整 SIRE 执行。

**不是简单任务时**：第二行写 `快速通道：否，完整流程`，然后按下方完整机制执行。

## 用户定义的 SIRE 完整机制

### 对话级需求与澄清门禁

以用户一次对话中提出的完整需求作为一个整体处理单位，不得擅自把用户需求缩减为单个子需求。必须先对整段需求进行需求分析，确认目标、范围、输入、输出、验收标准、依赖关系和授权范围均足够清晰后，才能进入拆解和执行。若整体需求存在实质不清晰、相互矛盾、缺少关键输入或验收标准不明确，必须立即中断执行，向用户明确列出：当前理解、存在歧义、影响范围、需要用户确认或补充的内容；在用户确认前，不得继续拆解、执行、修改外部状态或自行选择会改变结果的方案。用户确认后，才可以继续该次对话需求的完整 SIRE 流程。

SIRE 是所有任务的强制自动化处理机制，必须完整执行：

1. 从用户需求提炼关键词，检索数据库和向量数据库，关联已有知识。
2. 执行需求分析、任务拆解、分组和依赖分析，拆成最小可执行单元。
3. 根据分组和依赖，在读写集不冲突时并行分配给多个执行者。
4. 每个单元完成后依次进行独立 Review 和功能验收；验收不合格必须驳回重做，并记录失败原因和修复动作。
5. 同一错误重试达到 3 次仍未解决时，中断受影响流程并告知用户原因；其他不受影响的单元可继续。
6. 所有单元完成并验收后，对整体需求执行关联性、隐患、回归和待优化点 Review。相关联的优化点必须在本任务内解决；不相关的优化点在最终报告中提醒用户。
7. 最终执行知识收集：提炼关键知识、关键词、决策、验证结果和限制，写入 `@SIRE_ARCHIVE_ROOT@\sire_vectors.sqlite3`，后续检索优先匹配关键词。

## 模型分级与省 token 机制

主控（高级模型，如 Opus）不得包揽全部工作硬烧 token，必须按难度把角色/单元派给合适模型（Agent 工具 `model` 参数）：

| 难度 | 典型工作 | 模型 |
|---|---|---|
| 低 | 检索知识库、批量读文件/搜代码、机械改写、格式化、跑脚本与测试、写台账/归档记录 | `haiku`（子代理 `sire-low`） |
| 中 | 常规编码实现、单元复核、功能测试、文档整理 | Opus 5.5 + low 思考（子代理 `sire-mid`） |
| 高 | 需求澄清、架构/方案设计、复杂排错、整体 Review 与最终裁决 | Opus 5.5 + high 思考（主控或子代理 `sire-high`） |

### 模型选择门禁（R4 放行后、R5 执行前）

需求分析与拆解完成、R4 放行之后，主控必须先对每个单元做一次模型选择，再进入 R5。该门禁同样要输出“执行中”和“执行完毕”。

1. 逐个单元按以下依据判定难度：是否需要设计决策或取舍；是否跨多个文件或模块；出错后的影响和回滚难度；验收标准是否可以机械核对；是否有现成知识或模板可以直接复用。
2. 简单单元（可机械核对、无设计决策、影响面小）派给低成本模型执行；复杂单元（需要设计决策、跨模块、高风险或排错）保留当前模型执行。中间情况按上表派给中难度。
3. 无法确定难度时先用低一档模型；验收不达标再按规则 3 升级，不得为了保险一开始就全部用当前模型。
4. 整个任务只有一个极小单元时，直接在主控完成，并在门禁结论中写明“极小任务，主控直接执行”。
5. 门禁产物是每个单元的“单元编号 / 难度 / 模型 / 判定理由”清单，写入台账并在阶段报告中列出。
6. R6 复核、R8 集成和 R9 收尾的最终裁决不得降到低成本模型。

规则：
1. 派工时在台账记录每个单元所用模型；未注明默认按上表。
2. 低中难度单元主控只写精简指令、只读结论，不重复读取子代理已读内容。
3. 子代理结果不达标可升一级模型重做（haiku→Opus low→Opus high），计入返工次数；不得一开始就全部用高级模型。
4. 纯问答、单点小改等极小任务直接在主控完成，不为派工而派工（派工本身有冷启动成本）。
5. 输出保持简约：阶段日志一行一项，不复述大段文件内容。

## SIRE 输出契约

每一个阶段和角色都必须显式输出“执行中”和“执行完毕”的状态；不得省略不需要执行的角色。跳过时必须写明“跳过”和具体原因。每个阶段完成后必须列出产物、验证结果和阻塞项，使用清晰分段和换行格式。最终报告必须重复完整的阶段/角色日志、整体 Review、优化处理结果、知识归档结果和最终状态。

## 强制真实场景测试机制

1. R7 测试开始前必须先列出测试项目清单，包含测试编号、真实用户操作步骤、预期表现、实际表现、证据和结论。
2. 涉及 App、网页、桌面程序、文件选择器、系统设置、设备连接、发布产物或用户界面的任务，必须模拟真实用户操作；不得只读代码、只做静态分析、只运行函数或只做纸面推演来判定通过。
3. 真实场景测试必须实际打开目标 App/网页，执行点击、输入、选择、提交、等待、返回、重试、退出等用户路径，并检查界面表现、状态变化、错误提示、数据结果和最终状态。
4. R10 负责获得授权范围内的电脑原生操作；R7 负责测试结论。R10 不得替代 R7 判定通过，R7 不得用推测代替实际证据。
5. 缺少电脑操作工具、目标环境或权限时，测试必须标记 `BLOCKED-无法真实验证`，不得标记 PASS。
6. 正常路径和至少一条边界/异常路径都必须进行真实场景验证；失败后必须记录操作步骤、实际表现、失败原因和返工次数。

## Claude/Codex 共用源补充

- 唯一 SIRE skill 源：`<SIRE_ROOT>/workflow/shared/sire/`。Claude 的 `~/.claude/skills/sire-global-workflow/` 与 Codex 的 `~/.codex/skills/ai-dev-sire-workflow/` 必须链接到同一物理目录。
- 唯一 Claude/Codex 工作数据库：`<SIRE_ROOT>/data/sire_vectors.sqlite3`，暂不进 Git（超过 GitHub 100MB 单文件上限），本机实际路径见 `sire/data/DATABASE-RECORD.md`；知识目录为 `<SIRE_ROOT>/knowledge/global/`。脚本必须通过 `scripts/sire_paths.py` 解析；两端的 `SIRE_ROOT`、`SIRE_DATA_DIR`、`SIRE_VECTOR_DB`、`SIRE_KB_DIR`、`SIRE_EMBED_DIR` 和 `SIRE_TASK_ROOTS` 覆盖值必须相同。
- 系统级归档规则仍要求更新 `@SIRE_ARCHIVE_ROOT@\sire_vectors.sqlite3`；它是任务闭环归档位置，不得配置成 Claude 或 Codex 的独立工作库。收尾时将任务记录与可复用知识同步到该归档，并将工作流与知识改动提交到 Git（共享数据库只做备份与检查，暂不进 Git，见 `sire/data/DATABASE-RECORD.md`）。
- PowerShell 收尾命令中的 `$env:SIRE_ARCHIVE_ROOT` 对应本机的 `@SIRE_ARCHIVE_ROOT@`；`$env:SIRE_ARCHIVE_DB` 必须由 `Join-Path $env:SIRE_ARCHIVE_ROOT 'sire_vectors.sqlite3'` 得到。两者只是执行当前归档步骤的 shell 变量，不配置到任一客户端。
- 禁止在客户端 profile 目录下保留可写的第二份 SIRE skill、知识库或向量库。轻量 ZIP 与 Git 仓库目前都不含数据库；数据库只在本机，位置与恢复方法见 `sire/data/DATABASE-RECORD.md`，禁止 `git add -f` 提交它。
