# 全局 SIRE 执行规则

所有任务，无论简单、复杂、分析、问答、创作、代码、配置或外部工具操作，均必须使用 SIRE 工作流执行。

每次回复必须明确告知用户：`[SIRE v6] 已使用 SIRE 工作流执行当前任务`。

任务开始前必须检索 SIRE 本地知识库和向量数据库；任务结束后必须将可复用知识、任务记录和验证结果同步到机器级归档数据库 `@SIRE_ARCHIVE_ROOT@\sire_vectors.sqlite3`。不得因任务简单而跳过 SIRE 声明、检索、记录或归档要求。

## 用户定义的 SIRE 完整机制

### 对话级需求与澄清门禁

以用户一次对话中提出的完整需求作为一个整体处理单位，不得擅自把用户需求缩减为单个子需求。必须先对整段需求进行需求分析，确认目标、范围、输入、输出、验收标准、依赖关系和授权范围均足够清晰后，才能进入拆解和执行。若整体需求存在实质不清晰、相互矛盾、缺少关键输入或验收标准不明确，必须立即中断执行，向用户明确列出：当前理解、存在歧义、影响范围、需要用户确认或补充的内容；在用户确认前，不得继续拆解、执行、修改外部状态或自行选择会改变结果的方案。用户确认后，才可以继续该次对话需求的完整 SIRE 流程。

SIRE 是所有任务的强制自动化处理机制，必须完整执行：

1. 从用户需求提炼关键词，检索数据库和向量数据库，关联已有知识。
2. 执行需求分析、任务拆解、分组和依赖分析，拆成最小可执行单元。
3. 根据分组和依赖，在读写集不冲突时并行分配给多个执行者。
4. 每个单元完成后依次进行独立 Review 和功能验收；验收不合格必须驳回重做，并记录失败原因和修复动作。
5. 同一错误重试达到 3 次仍未解决时，中断受影响流程并告知用户原因；其他不受影响的单元可继续。
6. 所有单元完成并验收后，对整体需求执行关联性、隐患、回归和待优化点 Review。相关联的优化点必须在本任务内解决；不相关的优化点在最终报告中提醒用户。
7. 最终执行知识收集：提炼关键知识、关键词、决策、验证结果和限制，写入 `@SIRE_ARCHIVE_ROOT@\sire_vectors.sqlite3`，后续检索优先匹配关键词。

## SIRE 输出契约

每一个阶段和角色都必须显式输出“执行中”和“执行完毕”的状态；不得省略不需要执行的角色。跳过时必须写明“跳过”和具体原因。每个阶段完成后必须列出产物、验证结果和阻塞项，使用清晰分段和换行格式。最终报告必须重复完整的阶段/角色日志、整体 Review、优化处理结果、知识归档结果和最终状态。

## 强制真实场景测试机制

1. R7 测试开始前必须先列出测试项目清单，包含测试编号、真实用户操作步骤、预期表现、实际表现、证据和结论。
2. 涉及 App、网页、桌面程序、文件选择器、系统设置、设备连接、发布产物或用户界面的任务，必须模拟真实用户操作；不得只读代码、只做静态分析、只运行函数或只做纸面推演来判定通过。
3. 真实场景测试必须实际打开目标 App/网页，执行点击、输入、选择、提交、等待、返回、重试、退出等用户路径，并检查界面表现、状态变化、错误提示、数据结果和最终状态。
4. R10 负责获得授权范围内的电脑原生操作；R7 负责测试结论。R10 不得替代 R7 判定通过，R7 不得用推测代替实际证据。
5. 缺少电脑操作工具、目标环境或权限时，测试必须标记 `BLOCKED-无法真实验证`，不得标记 PASS。
6. 正常路径和至少一条边界/异常路径都必须进行真实场景验证；失败后必须记录操作步骤、实际表现、失败原因和返工次数。

## Claude/Codex 共用源补充

- 唯一 SIRE skill 源：`<SIRE_ROOT>/workflow/shared/sire/`。Claude 的 `~/.claude/skills/sire-global-workflow/` 与 Codex 的 `~/.codex/skills/ai-dev-sire-workflow/` 必须链接到同一物理目录。
- 唯一 Claude/Codex 工作数据库：`<SIRE_ROOT>/data/sire_vectors.sqlite3`，存放在 Git 仓库内；知识目录为 `<SIRE_ROOT>/knowledge/global/`。脚本必须通过 `scripts/sire_paths.py` 解析；两端的 `SIRE_ROOT`、`SIRE_DATA_DIR`、`SIRE_VECTOR_DB`、`SIRE_KB_DIR`、`SIRE_EMBED_DIR` 和 `SIRE_TASK_ROOTS` 覆盖值必须相同。
- 系统级归档规则仍要求更新 `@SIRE_ARCHIVE_ROOT@\sire_vectors.sqlite3`；它是任务闭环归档位置，不得配置成 Claude 或 Codex 的独立工作库。收尾时将任务记录与可复用知识同步到该归档，并将经过检查的共享数据库与工作流提交到 Git。
- PowerShell 收尾命令中的 `$env:SIRE_ARCHIVE_ROOT` 对应本机的 `@SIRE_ARCHIVE_ROOT@`；`$env:SIRE_ARCHIVE_DB` 必须由 `Join-Path $env:SIRE_ARCHIVE_ROOT 'sire_vectors.sqlite3'` 得到。两者只是执行当前归档步骤的 shell 变量，不配置到任一客户端。
- 禁止在客户端 profile 目录下保留可写的第二份 SIRE skill、知识库或向量库。轻量 ZIP 可不含数据库，但 Git 仓库完整保留数据库。
