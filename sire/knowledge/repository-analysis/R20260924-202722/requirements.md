# SIRE 需求分析

## 目标
分析 @CODE_ROOT@ 下可识别的全部项目源码，提炼便于后续开发/排障复用的架构与入口信息，写入 @SIRE_ROOT@/sire_vectors.sqlite3。

## 范围
- 14 个顶层 Git 仓库；另纳入 3 个无 Git 元数据但含源码的项目目录：claude-code、mes、mes-admin。
- EncoderPlotter 与 recalibration 仓库中的 Git 子模块，按组件类型分析职责，并记录各顶层项目固定的 gitlink 提交。
- 每个记录含项目定位、当前分支/HEAD/状态（有 Git 时）、技术栈、入口/核心模块、依赖关系、构建/测试路径、风险/限制、可验证文件来源。

## 非目标与边界
- 只读分析源码；不改业务仓库，不运行固件，不触发发布、设备写入或外部服务操作。
- 不将全部源码、密钥、.env 内容、用户测量数据、日志、二进制、缓存或构建产物批量导入数据库。
- 不运行项目测试或构建；验收以来源核对和数据库索引验证为准。

## 输入/输出
- 输入：@CODE_ROOT@ 下项目文件与 Git 元数据；既有 SIRE 知识库和向量库。
- 输出：精炼的项目知识记录、跨项目索引、SIRE 台账与验证记录；数据库为正式归档目标。

## 验收标准
- AC-01 清单覆盖所有顶层 Git 根、3 个源码型无 Git 目录和已发现子模块组件，无把编辑器配置/缓存误算为仓库。
- AC-02 每个项目知识条目均含关键入口/架构、关键文件路径、依赖/构建测试信息和明确限制；关键事实可回到文件或 Git 元数据核验。
- AC-03 仅新增提炼后的知识与任务台账，不新增全源码 chunks；数据库事务完成且 integrity_check 为 ok。
- AC-04 FTS 与向量检索可命中新项目知识，表计数与 run 记录一致。
- AC-05 汇总说明未运行项目测试/真实设备路径，不将静态分析误称为功能运行通过。

## 风险
工作区包含 .env、日志、样本和大型生成数据；归档前复核只存摘要与必要路径，不含敏感值或大体积数据。
