# 可复用知识模板

> **收录标准（用户定，2026-09-24）**：每一条都必须是**实际发生过的真实经验**，并且**可以直接使用**——踩坑、经验、可复用方案都可以；无效的、没有意义的内容（流水账、过程日志、空模板、一次性问答、已废弃项目、被取代的中间版本）一律不收。

> 目标：别人（或以后的 Claude）只看这一条记录，就能在新项目里把同样的功能做出来 / 把同样的问题修好。
> 新增：把下面的正文写进一个文件，然后 `python <SHARED_SKILL_DIR>/scripts/sire_kb.py add P --title "标题" --file 正文.md`，再执行 `sire_vector_db.py index` 入库。
> 检查：`sire_kb.py lint` 列出缺段落的记录。

**日期**: YYYY-MM-DD
**项目**: 项目名 / 仓库路径
**关键词**: 中文术语, English term, 函数名, 报错原文, 同义说法（逗号分隔，越具体越好）

**需求场景 / 现象**: 要做什么功能，或者出现了什么问题（带报错原文、复现条件）。

**根因**（问题类必填）: 为什么会这样，定位到哪一层。

**方案 / 架构**: 最终怎么做的；关键设计取舍和被否决的方案（及原因）。

**关键文件与接口**:
- `path/to/file.py:行号` — 函数/类名，做了什么
- 配置项、命令、协议字段

**实施步骤**:
1. …
2. …

**核心代码片段**（可选，只放最关键的 5~30 行）:
```
…
```

**验证方法**: 怎么证明做对了（命令、测试、真机步骤、期望输出）。

**踩坑**: 做的过程中踩过的坑和解法。

**状态**: 已完成 / 部分完成 / 已废弃
