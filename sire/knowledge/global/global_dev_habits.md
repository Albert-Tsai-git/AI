### H-005: 按任务复杂度和验收风险选择模型以控制成本
**日期**: 2026-10-12
**项目**: Codex SIRE shared workflow
**关键词**: 模型选择, 低成本模型, token 成本, 复杂度分级, task routing, model escalation

**需求场景 / 现象**: 用户要求智能体先判断每个任务单元的复杂度与执行风险，选择相称的模型，降低简单工作的 token 成本，同时保持验收质量。

**方案 / 实施步骤**:
【方案 / 架构】沿用共享契约已有的模型选择门禁，不固定某个型号为永久规则。简单检索、机械修改和现成检查等易核验、低影响工作优先使用当时可用的低成本模型；常规实现按工作复杂度选择适当档位；需要设计取舍、复杂排错、高风险决策及最终裁决留给高档模型。极小任务不为派工而增加代理开销。选择时一并考虑上下文切换、返工成本和错误影响；首次低档执行未通过验收时，逐级升级模型。
【实施步骤】1. 对任务单元按复杂度、影响、可核验性和返工成本选择模型。
1. 在 run 台账注明实际模型及理由；记录升级或验收结果。
2. 将常态偏好与本次实际执行所用模型分开记录，型号随当前可用选项而变化。

**验证方法**: 本次 U1 为低难度、机械归档单元，R4 已批准复用既有规则；实际由 `gpt-6-luna low` 执行。本型号只作为本次事实，不代表长期固定偏好。

**踩坑 / 已知异常与失败经验**: 首次 Markdown 检索传入不存在的回执目录，脚本未记录回执；随后在正确 run 目录重跑并成功记录。归档前通过历史配置与只读检查确认 `D:\sire\sire_vectors.sqlite3` 是既有机器级 SIRE 共用运行库。

**关键文件与接口**: - `workflow/shared/sire/references/global-contract.md` — 已有 R4 后模型门禁、难度分级及升级规则，本记录只归档用户稳定偏好。
- `scripts/sire_paths.py` — 解析 Claude/Codex 共用知识库和 SQLite 路径。

### H-009: 改 CI 脚本先本地测试好再提交推送，不要把 pipeline 当调试循环
**日期**: 2026-11-05
**项目**: quality-testing/dv3-admin
**关键词**: CI, 流水线, 本地测试, 推送, pipeline, 调试循环, 提交信息

**需求场景 / 现象**: 用户要求改 CI 脚本；排查 deploy 阶段时曾连续推送多次，每次都触发完整打包和上传。用户原话：“本地测试好再提代码，不要在 pipeline 里面测试”。

**方案 / 实施步骤**:
1. 能在本机复现的部分（PowerShell 片段、YAML 语法、ACL 操作、变量注入解析）先本地跑通。
2. 本地无法覆盖的部分明确告诉用户，由用户决定是否推送，不自行连续推送迭代；推送前仍需用户确认。
3. 用户事后明确说“多测试几次打包和部署”时，才可在授权范围内多次触发流水线，优先用手动触发同一提交的方式，不为触发而新增提交。

**踩坑 / 已知异常与失败经验**: 把 pipeline 当调试循环会每次触发完整打包和上传；技术约束另见 P-20261105：该仓库的提交信息用英文。
